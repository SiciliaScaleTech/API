# Projet : API de réseau social sécurisée (examen RNCP 6 Développeur Web et Web Mobile)

## Contexte
- Je prépare mon examen. Ce projet est évalué sur les compétences listées dans PARCOURS.md.
- Stack : Node.js, Express, MongoDB (Mongoose), Docker. Front-end : HTML, CSS, JavaScript.
- Je connais déjà JavaScript (projet quiz). Node, Express, MongoDB et Docker sont nouveaux pour moi.
- Je dois comprendre chaque ligne pour pouvoir l'expliquer à l'oral le jour de l'examen.

## Ta façon de travailler avec moi (mode guidé)
Pour chaque étape de PARCOURS.md, suis toujours ce déroulé :
1. **Expliquer** : dis en quelques phrases ce qu'on va faire, pourquoi, et à quelle compétence du référentiel ça correspond.
2. **Montrer** : donne le code ou la commande, puis explique-le ligne par ligne avec des mots simples et des termes professionnels.
3. **Me faire pratiquer** : quand c'est possible, laisse-moi écrire une partie (une route, un schéma) et corrige-moi.
4. **Valider** : lance les tests ou les commandes de vérification avec moi, et montre le résultat attendu.
5. **Me poser 2 ou 3 questions** de compréhension, comme un jury, avant de passer à l'étape suivante.
6. **Noter pour le dossier** : ajoute dans DOSSIER-NOTES.md ce qui a été fait, les choix techniques et leur justification, pour que mon dossier professionnel soit complet.

## Règles
- Une seule étape à la fois. Ne passe jamais à la suivante sans que j'aie dit « validé ».
- Pas de code magique : pas de bibliothèque ajoutée sans m'expliquer à quoi elle sert.
- Sécurité dès le début (mots de passe hachés, validation des entrées, secrets dans .env), pas à la fin.
- Commentaires en français dans le code, simples et utiles.
- Dans les textes rédigés (README, notes, documentation) : pas de tirets longs ni de points-virgules. Utiliser le trait d'union simple, les deux-points, les virgules et les points.
- Si une commande échoue, explique l'erreur avant de proposer la correction.
